# RQ2 Protocol — Autonomy Spectrum Trade-offs (Conditions A / B / C)

**How this feeds RQ0:** doppelgänger research is not one paradigm, psychology-style studies need full scripted control, SEAM-style studies need constrained-but-autonomous agents, and exploratory HCI studies want to see what the AI does unprompted. RQ2 asks whether the same SDK can support all three without the researcher fighting the tool. A SDK that only serves one end of the spectrum is only "suitable" for a narrow slice of doppelgänger research — that's the finding RQ2 contributes back to RQ0, distinct from RQ1's "does the feature exist" question.


**Important framing:** these three conditions are not being ranked against each other to find a "best" mode. Each is the correct choice for a different kind of study; RQ2 documents what each one costs the researcher, so a future doppelgänger researcher can pick the right condition for their paradigm with eyes open.


## 1. The three conditions — overview

| Condition | Maps to research paradigm | Control mechanism | Feasibility |
|---|---|---|---|
| **A — Wizard-of-Oz** | Psychology-style scripted experiments | Human operator manually triggers `agent.Speak()` / `agent.PerformAction()` / `agent.ExpressEmotion()` via a custom UI | Feasible, but **not natively supported** — requires building a ~200-line operator panel |
| **B — Constrained AI** | SEAM-style bounded autonomous agents | AI-driven via `GeminiLiveAgent`, constrained through the `additionalDescription` system-prompt field | Feasible — edit only, no custom UI needed |
| **C — Fully autonomous AI** | Exploratory / open-ended HCI research | SDK's existing `GeminiLiveAgent` sample, unmodified | Already exists — zero additional setup |
